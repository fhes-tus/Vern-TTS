# Vern desktop architecture

Decision recorded 17 October 2026. The new application lives in `desktop/`. Android and the earlier Compose experiment in `veritas-pc/` remain separate and unchanged.

## Ownership and boundaries

- Tauri 2 hosts React + TypeScript, built with Vite. CSS tokens reuse Android's light palette, Outfit UI, Bitter reader and Atkinson accessibility fonts. Desktop spacing is provisional; the hierarchy follows `docs/VISUAL_SYSTEM.md`.
- The shell follows Android's four destinations in their actual visual order: Home, Library, Study, Notes. Added/Classics are nested under Library; flashcards, vocabulary/pronunciation and AI handoff are nested under Study. Listening queue/Voice Studio are reached from Home, the player or Settings. Settings live behind the header gear, and reader preferences open directly from the reading toolbar. The empty player is hidden until a book is active. Home shows real library/note/due-card counts, never fabricated session statistics.
- `themes.ts` applies checked-in palettes ported from `VeritasColorSchemeCatalog.kt`: six Android families, accessibility presets and two additional colour presets. Light/dark/system mode tracks the OS; fixed dark/light presets explain their supported mode. Custom hex accents select contrasting button text. These choices, reader appearance and reduced motion persist only through native settings, with defaults for older JSON. Original document paper keeps source colours. OS reduced motion and the app setting both disable transitions.
- Rust exclusively owns SQLite, settings, native file dialogs, downloads, installed-model validation and speech. Frontend storage plugins are deliberately omitted to avoid a second data owner. Books are plain text chunks rendered as React text. Source-document views use PDF.js canvas/text layers or a bounded structured model rendered with React; publisher HTML and scripts are never inserted into the webview.
- Import parsers run in a web worker. EPUB uses bounded ZIP decompression and OPF spine ordering; PDF.js extracts text in page order. DOCX extracts WordprocessingML paragraph text and PPTX follows presentation slide relationships before extracting DrawingML paragraphs. All archive formats share entry-count, path and expansion bounds; external slide relationships are rejected. Office metadata comes from core properties. TXT/Markdown use strict UTF decoding. The native chooser reads only the selected file, with a size limit. Pasted text goes through the same worker and native save path.
- `documents.rs` retains source files up to 32 MB in SQLite with validated page-to-chunk indices and a separate saved original-page position. PDF.js renders actual PDF canvas pages and selectable text with bounded raster size. Locked PDF.js font/CMap/WASM assets are served locally and included in the frontend bundle. Word/EPUB/PowerPoint source workers reconstruct paragraphs, tables and bounded embedded raster images; PPTX uses slide positions. Word pagination/fonts, slide themes/group transforms and EPUB publisher CSS are not exact. No OCR, remote source assets, publisher scripts or speaker notes are supported. Image-only PDFs are explicitly view-only. Older text-only imports require reimport to attach bytes. Source blobs are excluded from current JSON backups.
- SQLite stores books, ordered chunks, positions, collection names, anchored notes/bookmarks, flashcards with review schedules, original source bytes/page indices, and settings. Schema v2 adds collections and flashcards; v3 adds source storage and text availability; v4 adds catalogue provenance; v5 adds quizzes and native results; v6 adds notebooks and personal notes. It is a versioned desktop database under Tauri's application-data directory, not a direct mutation of Android's database. Content hashes deduplicate imports. Book deletion cascades to linked annotations/cards/source bytes and clears the saved resume target in one transaction. Unlinked flashcards remain independent.
- `ReaderSurface.tsx` owns transient pagination, selection and gesture state. Responsive flow pages preserve chunk and character offsets; single/two-page turns keep native speech/note anchors. Reader layout/view preferences persist through Rust. The reader occupies its workspace, with the notebook closed by default. Fullscreen uses Tauri's narrowly granted `set_fullscreen` command, hides app chrome and overlays auto-hiding controls. Page turns, navigation, dialogs and other app transitions respect reduced-motion settings. An explicit absolute `VERN_PROFILE_DIR` override isolates Rust SQLite/models and Tauri WebView/cache directories before initialization in debug and release builds. Invalid, relative, root or traversal paths stop startup. Without it, normal application data is used. The older debug-only `VERN_DEV_DATA_DIR` override remains for native development checks.
- `storage.rs` owns library/settings/annotation commands; `study.rs` owns flashcard validation and scheduling. The frontend supplies card content and review ratings, never computed due dates or ease factors. Scheduling ports Android's SM-2 Lite rules from `StudyAssistant.kt`. React owns only transient filters, forms and review queues. Source passage links retain book/chunk anchors across note/card edits.
- `classics.rs` shares checked-in catalogue metadata with the cover UI. It accepts IDs, never arbitrary download URLs, for 36 direct Project Gutenberg text editions from Android. Native downloads have two slots, cancellation, time/size bounds (16 MB), HTTPS host-restricted redirects and UTF-8/text checks. Reading text passes through the import worker; complete original bytes including the licence are retained. Schema v4 adds a cascading catalogue-to-book link so renamed installed books open from Classics without resetting progress. Source bytes/catalogue links are outside current JSON backup; downloading again can reconnect a matching restored book through content deduplication. Native network acceptance is tracked separately in progress.md.
- `AiHandoff.tsx` prepares editable explanation, summary, flashcard and study-note prompts with bounded context and keeps its transient draft across in-app navigation. Clipboard copy and explicit provider opening are user actions. `handoff.rs` accepts known provider IDs and opens fixed HTTPS websites through the OS without putting context in URLs or submitting prompts. AI replies are not automatically read/imported. Study Hub previews bounded pasted card/quiz replies (JSON, tables and marked text) before native persistence. Direct AI generation remains outstanding parity work.
- Settings JSON in the same Rust-owned SQLite database stores bounded listening queues, vocabulary and pronunciation rules. New fields deserialize with defaults for existing libraries. Queue references and vocabulary source positions are validated natively; book deletion removes queued references and detaches vocabulary without deleting definitions. Failed optimistic preference changes revert to the last native-persisted snapshot. `reading_tools.rs` performs speech-only pronunciation edits before synthesis, preserving displayed text and source indices; regex is used for Unicode-aware literal phrase matching and boundary checks.
- `transfer.rs` owns desktop JSON backup validation/merge and text/Markdown/WAV serialization. Backups use `vern.desktop.backup.v1` and are bounded to 64 MB and 20,000 entries per top-level collection. Validation uses the normal native validators against an isolated in-memory database before returning counts and an opaque, single-use confirmation token. Restore merges in a SQLite savepoint with rollback on failure, preserving existing identities/progress/schedules. Queue, vocabulary and pronunciation data merge independently of the optional reader-preference restoration. Native save dialogs choose destinations; exports use sibling staging files, sync, and rename. Voice models/source attachments and Android backup migration are outside this format. Audio export currently synthesizes one anchored passage as 16-bit mono PCM WAV.
- Speech uses upstream `sherpa-onnx` Rust bindings and the same model families as Android. **Studio = Kokoro; Lite = Piper.** Static native linking is preferred so the installed app needs no developer runtime or Python/Node helper. Native archive acquisition happens at build time; models are downloaded by the app.
- A blocking speech worker owns the loaded engine. Requests carry a generation counter; obsolete synthesis is cancelled and its results discarded. The webview plays generated PCM WAV via Web Audio. Highlighting is per chunk, with progress advanced on completion. No word timing is claimed.
- Downloads have two execution slots, cancellation flags, temporary staging, bounded safe archive extraction and model validation before atomic publication. URLs are fixed catalogue entries, never frontend-supplied destinations. Failed/interrupted staging never counts as installed.

## Dependency purposes

React/React DOM: interface. TypeScript 6: typed command payloads (TypeScript 7 is beyond the lint tooling's supported range). Vite/React plugin: build and dev server. Tauri API/CLI: IPC and native packaging. `fflate`: bounded EPUB ZIP data. `@xmldom/xmldom`: EPUB XML/XHTML parsing inside a worker. `pdfjs-dist`: PDF text extraction and worker. ESLint 10/Prettier: source checks. Vitest/Testing Library: import and UI behavior. Playwright: browser inspection (independent of native checks).

Rust: `tauri`/`tauri-build` host and build integration; `tauri-plugin-dialog` native chooser (Rust-only API, so no unused JavaScript dialog package/permission is installed); `rusqlite` with bundled SQLite is the sole database owner; serde/serde_json command payloads; reqwest/rustls fixed HTTPS model downloads with the ring provider to avoid an AWS-LC/CMake dependency; tokio worker coordination; tar/bzip2 model archives; sha2 content integrity and deduplication; uuid note identifiers; sherpa-onnx native offline speech; unicode-normalization speech cleanup.

Download catalogue digests were verified against the official GitHub `tts-models` release asset metadata and the downloaded bytes on 17 October 2026. Lessac: `f1c6d0295cf16087b05f80fdca5b44daca5cd78e2c425d419a42ba34929805f9`. Kokoro v1.0: `4c3052abaa60943a341f193888cf6abd68787dae6ab8ae5c925a706caa247e4e`. Changed upstream assets require a deliberate catalogue update. Cancellation is checked between streamed reads and extraction entries; blocked network operations have a 20-second timeout. Downloads are restarted rather than resumed. Native inference remains sequential; the frontend now prefetches at most one future passage while current audio plays. Prefetch failures are handled immediately, and stale generations are discarded. This is not sample-accurate gapless scheduling or measured latency improvement. A transient sleep deadline schedules current Web Audio source stopping and prevents continuation. Android DSP parity remains later work.

## Release preparation

Native runners build Windows x64, Linux x64, and macOS Intel/Apple Silicon. CI builds are unsigned validation artifacts until signing is configured. Windows needs Authenticode; macOS needs Developer ID, hardened runtime, notarization and stapling. Linux needs distro/WebKitGTK compatibility validation. Audit model licences and include upstream runtime notices before distribution. Models remain optional app downloads, never require npm or Cargo on end-user machines. Configure an updater only after establishing signed release artifacts, a signing key outside the repo and an HTTPS update endpoint. No updater permission is granted yet.

`quizzes.rs` owns quiz validation, source references, saved attempts/best and last correct-answer counts. Submission supplies option indices; native code computes scores. Question edits reset old scores, title edits preserve them. Card imports use a savepoint and reject the entire batch on a validation failure. Quiz data is included in version-1 desktop backups with a default for older files; restore validates and merges without replacing existing quiz identities.

`notes.rs` owns standalone notes/checklists, notebook labels, colours, pinning and Trash state, with native timestamps and limits. Notebook removal unlinks labels transactionally while preserving notes. Permanent deletion requires an already trashed note. `NotesWorkspace.tsx` embeds My notes, Book notes/bookmarks and Trash within the Notes destination. Native backups validate label references and merge notebooks before notes, retaining existing identities. Media, reminders and note revision history remain separate parity work.

## 29 October 2026 — Reading workspace and native settings

- The reader owns its book toolbar and playback footer independently of general app chrome. It uses a 56-pixel navigation rail, adjacent Previous/Next controls, Enter submission for page jumps (including even pages in two-page mode), on-demand search/notebook overlays, bounded text sizing and trackpad Ctrl-wheel pinch. Original documents use page zoom. Native settings include System default, Bitter/Gazette, Outfit/Crisp, Times/Typewriter, Atkinson and Georgia; line spacing and paper tones also drive pagination and the preview. Only the PDF text-selection stylesheet is included: the complete PDF.js viewer stylesheet previously leaked sidebar widths and other chrome into Vern.
- Settings have route-aware categories, with a category picker at narrow desktop widths, and Back/Forward/Close restore the entry context. Notes defaults (paper guides, scale/spacing, checklist behavior, preview lines, layout and sorting), accessibility controls, PDF page-range/text cleanup defaults and preferred AI assistant persist through Rust. AI/study mode explains the existing reviewed handoff/reply-import workflow; direct API/local generation remain separate work. About uses the Android identity, fixed native contact/community destinations and bundled font notices. No updater permissions were added.
- Schema v7 adds reading sessions; schema v8 adds optional cover thumbnails to books. Native monotonic timing owns measured reading/listening time, idle/suspend handling, manual sessions/corrections/exclusion, local-day totals, goals/streaks and CSV export. The frontend only reports activity/input and actual Web Audio output; it never supplies elapsed totals. Sessions are included in native JSON backup/merge.
- Imports and cover extraction run in a worker. PDF covers inspect up to five bounded pages using offscreen intermediate canvases, outlined fonts and explicit worker fetch of bundled PDF assets. EPUB cover declarations and Office thumbnails/first embedded raster images are supported. Source images are bounded to 8 MP and thumbnails to 400 by 600 pixels / 256 KiB JPEG. Rust validates the bounded data URI and JPEG dimensions, stores it in SQLite and preserves progress when adding a thumbnail. Existing retained sources are backfilled sequentially. Backups include thumbnails; original source files still remain excluded. Missing covers use the Android GeneratedBookCover palettes, real titles/authors and folded-page artwork as SVG, without a second persistence owner.
- Voice acquisition now loads the graph at its stable final directory before atomically publishing the installed marker. Sherpa/eSpeak initializes its data path once per process, so validating in a temporary directory that is later renamed broke first-install playback. Failed/cancelled packages are unpublished. Current official Kokoro v1.0 archive SHA-256 is 72c347230107ef8a31098ec4d468a605244beef5f1ed00db97efa13518800653; the previously verified 4c3052abaa60943a341f193888cf6abd68787dae6ab8ae5c925a706caa247e4e remains accepted for existing installations. Speaker mapping stays Heart ID 3; Lite remains Piper.

### Library selection and narration ranges

LibraryShelf owns only transient query/filter/sort/selection state. Right-click enters selection mode; ordinary browsing has no checkboxes. Individual and batch actions reuse Rust's book/settings commands. Native deletion cleans related data and queue/resume references; the frontend refreshes the library/settings and removes only deleted reader drafts, including after partial batch failures. Finished books follow Android's saved-final-passage boundary and remain after unfinished books under every sort.

Spoken ranges follow actual Web Audio output, independent of the persisted reading location. CSS Highlight ranges use existing plain-text/source/PDF selectable nodes without changing DOM text or the user's Selection. They are bounded per visible text container and removed when output stops. Manual selection defers automatic page following. A short single-click delay prevents double-click word selection from stopping narration. The selection toolbar chooses the opposite end when first-line text is selected.

## Android migration reader — 2 November 2026

`android_backup.rs` now reads Android JSON/full-ZIP exports in Rust, validates schema/sections/document IDs and bounded page/sentence metadata, supplies one document's exact UTF-16 worker input, and retains metadata plus private staged original/media/cover payloads. The shared desktop ZIP envelope/path/compression/duplicate/symlink/expansion checks are reused. Archive names are lookup keys, not filesystem destinations; staged files use native-owned random names and RAII cleanup. Attachment manifest size/hash checks occur before conversion. Reader limits remain 64 MB metadata, 32 MB reading text/original files, 8 MB attachment/cover payloads and 20,000 section/archive entries within 2 GB total expansion.

This reader is not yet connected to the restore commands. The existing `AndroidIndexer` worker port preserves Kotlin UTF-16 sentence/page rules; native converted-result validation, mappings for library positions/notes/study/settings, worker coordination and single-use native preview/merge still need implementation. The normal restore UI therefore continues to reject Android backups. No SQLite schema, persistence owner, inference runtime or original Android application build/UI was changed by this reader stage.



## Android restore coordinator and provenance — 4 November 2026

`android_restore.rs` owns a transient Android backup plus sequential validated `ConvertedReading` values. Native chooser inspection returns either the normal desktop preview or a conversion token/count. `backup-conversion.ts` obtains one native text payload at a time and uses `AndroidIndexer` in a worker; it acknowledges each result before requesting the next. It owns no persistence. Abort/errors/navigation terminate the worker and discard the native conversion/preview. Only Rust validates the resulting native records, publishes the single-use preview, and performs the existing savepoint merge. No book/note/card is persisted during parsing.

`android_archive.rs` owns retained source metadata and original archive asset bytes under SQLite schema 14. Source paths are opaque keys, never filesystem destinations. Retained assets have checked sizes/SHA-256, private staging leases and a deterministic import identity over metadata plus the sorted asset manifest. Desktop full-backup metadata v4 preserves these records; archive entries use `android_imports/<64 lowercase hex>/<64 lowercase hex>.bin`. Earlier desktop formats remain readable. Original Android ZIP export writes semantically identical metadata plus byte-identical included files through bounded native staging. Separate confirmed deletion cascades only to retained-import assets; imported library and note media remain independent.

Supported Android data maps into existing native models and validators. UUIDs are preserved, with deterministic namespaced identities for legacy IDs. Android whole-book cards may carry a book without a passage; a passage still requires a valid book. Imported quiz best scores may exist with zero desktop attempts/unknown last score, and desktop UI labels attempt counts accordingly. Android voice preferences use bounded explicitly unavailable portable IDs, so inference still requires an explicitly selected supported descriptor. No silent engine fallback is added.

Unconverted source data remains visible as preview limitations and recoverable in retained exports. It is not counted as usable desktop sessions/templates/reminders/media merely because the raw data is preserved. Current limits and verification scope are in the parity checklist and progress.md. No release packaging or normal-profile migration was performed in this pass.


## Android session history — 4 November 2026

Rust `android_history.rs` converts recorded Android sessions using pinned `chrono-tz` 0.10.4 / IANA 2025b. It uses the earlier overlap offset and first valid instant after a midnight gap, including skipped dates, corresponding to Android's `LocalDate.atStartOfDay`. Date encounter order is preserved for correction allocation. Original session JSON remains attached to the native session and is revalidated against immutable measured spans/day allocation during backup import. Corrections/exclusions may change through the existing native commands without rewriting that original record.

Native `Session` passage positions are `Option<usize>`; earlier numeric JSON still reads as known positions. Android cached-file revision strings cannot establish historical anchors in an exported current reading, so those imports have unknown native passage positions while retaining original indices/pages/revision in `androidSource`. Book association remains useful for totals and current-book navigation. Unknown source passage cells export blank in CSV. Zero-duration sessions remain history records with no invented time/dates. Long imported totals are bounded, while live/manual session commands retain their 24-hour cap; proportional arithmetic uses u128 to avoid overflow. Session provenance survives deletion of the separately retained original Android backup and round-trips in desktop full backups.

No persistence owner moved into the frontend. Insights only presents the native records and uses explicit measured-duration preservation when editing a long imported session. No model/network/runtime timezone service or Android Gradle/UI change was added. Current verification and TZDB/actual-device limits are recorded in progress.md and the parity checklist.


## Recent books and Android preferences — 4 November 2026

`opened_books.rs` owns recent-book navigation history under SQLite schema 15. Its nullable foreign key detaches when a book is deleted; native listing uses current titles without reloading full texts. Native timestamps, bounded rows/fields and a savepoint upsert/prune keep at most 40 entries. Restore merges by newest recorded opening and may reconnect restored content identities without overwriting book progress. Separate commands record/list/remove/clear history through blocking Rust work. React records reader entry and actual book-audio activation, displays history and opens current book state; it owns no additional persistence. History is distinct from measured sessions.

Desktop full-backup metadata v5 includes `openedBooks` (default empty for earlier formats). Validation checks linked native identities and bounds before the existing transactional merge. JSON and ZIP exports retain this data; v1–v4 remain readable. Android records keep original source JSON and unknown native historical anchors. Missing-book Android history uses a deterministic hash identity. The 40 newest converted entries become native history; excess source records remain in the retained original backup with a preview warning.

`android_settings.rs` converts supported preference values into existing native Settings, preserving missing fields and warning rather than substituting unsupported choices. Theme/font aliases follow authoritative Android catalogues. Font transfer affects reading text, not the desktop navigation typeface. Android editor-line-spacing multipliers cannot be equated to the desktop CSS line-height ratio, so the current desktop value remains. Complete original preferences stay in retained Android metadata; provenance retention does not count unconverted settings as parity. Restore's existing explicit apply/keep-current choice remains authoritative. No new settings store, Android Gradle/UI change, voice substitution or dependency was added.
