# Vern desktop architecture

Decision recorded 17 October 2026. The new application lives in `desktop/`. Android and the earlier Compose experiment in `veritas-pc/` remain separate and unchanged.

## Ownership and boundaries

- Tauri 2 hosts React + TypeScript, built with Vite. CSS tokens reuse Android's light palette, Outfit UI, Bitter reader and Atkinson accessibility fonts. Desktop spacing is provisional; the hierarchy follows `docs/VISUAL_SYSTEM.md`.
- The shell follows Android's four destinations in their actual visual order: Home, Library, Study, Notes. Added/Classics are nested under Library; flashcards, vocabulary/pronunciation and AI handoff are nested under Study. Listening queue/Voice Studio are reached from Home, the player or Settings. Settings live behind the header gear, and reader preferences open directly from the reading toolbar. The empty player is hidden until a book is active. Home shows real library/note/due-card counts, never fabricated session statistics.
- `themes.ts` applies checked-in palettes ported from `VeritasColorSchemeCatalog.kt`: six Android families, accessibility presets and two additional colour presets. Light/dark/system mode tracks the OS; fixed dark/light presets explain their supported mode. Custom hex accents select contrasting button text. These choices, reader appearance and reduced motion persist only through native settings, with defaults for older JSON. Original document paper keeps source colours. OS reduced motion and the app setting both disable transitions.
- Rust exclusively owns SQLite, settings, native file dialogs, downloads, installed-model validation and speech. Frontend storage plugins are deliberately omitted to avoid a second data owner. Books are plain text chunks rendered as React text. Source-document views use PDF.js canvas/text layers or a bounded structured model rendered with React; publisher HTML and scripts are never inserted into the webview.
- Import parsers run in a web worker. EPUB uses bounded ZIP decompression and OPF spine ordering; PDF.js extracts text in page order. DOCX extracts WordprocessingML paragraph text and PPTX follows presentation slide relationships before extracting DrawingML paragraphs. All archive formats share entry-count, path and expansion bounds; external slide relationships are rejected. Office metadata comes from core properties. TXT/Markdown use strict UTF decoding. The native chooser reads only the selected file, with a size limit. Pasted text goes through the same worker and native save path.
- `documents.rs` retains source files up to 32 MB in SQLite with validated page-to-chunk indices and a separate saved original-page position. PDF.js renders actual PDF canvas pages and selectable text with bounded raster size. Locked PDF.js font/CMap/WASM assets are served locally and included in the frontend bundle. Word/EPUB/PowerPoint source workers reconstruct paragraphs, tables and bounded embedded raster images; PPTX uses slide positions. Word pagination/fonts, slide themes/group transforms and EPUB publisher CSS are not exact. No OCR, remote source assets, publisher scripts or speaker notes are supported. Image-only PDFs are explicitly view-only. Older text-only imports require reimport to attach bytes. Source blobs are excluded from current JSON backups.
- SQLite stores books, ordered chunks, positions, collection names, anchored notes/bookmarks, flashcards with review schedules, original source bytes/page indices, and settings. Schema v2 adds collections and flashcards; v3 adds source storage and text availability; v4 adds catalogue provenance; v5 adds quizzes and native results; v6 adds notebooks and personal notes. It is a versioned desktop database under Tauri's application-data directory, not a direct mutation of Android's database. Content hashes deduplicate imports. Book deletion cascades to linked annotations/cards/source bytes and clears the saved resume target in one transaction. Unlinked flashcards remain independent.
- `ReaderSurface.tsx` owns transient pagination, selection and gesture state. Responsive flow pages preserve chunk and character offsets; single/two-page turns keep native speech/note anchors. Reader layout/view preferences persist through Rust. The reader occupies its workspace, with the notebook closed by default. Fullscreen uses Tauri's narrowly granted `set_fullscreen` command, hides app chrome and overlays auto-hiding controls. Page turns, navigation, dialogs and other app transitions respect reduced-motion settings. The debug build supports an absolute `VERN_DEV_DATA_DIR` override for isolated native checks; release builds always use normal application data.
- `storage.rs` owns library/settings/annotation commands; `study.rs` owns flashcard validation and scheduling. The frontend supplies card content and review ratings, never computed due dates or ease factors. Scheduling ports Android's SM-2 Lite rules from `StudyAssistant.kt`. React owns only transient filters, forms and review queues. Source passage links retain book/chunk anchors across note/card edits.
- `classics.rs` shares checked-in catalogue metadata with the cover UI. It accepts IDs, never arbitrary download URLs, for 36 direct Project Gutenberg text editions from Android. Native downloads have two slots, cancellation, time/size bounds (16 MB), HTTPS host-restricted redirects and UTF-8/text checks. Reading text passes through the import worker; complete original bytes including the licence are retained. Schema v4 adds a cascading catalogue-to-book link so renamed installed books open from Classics without resetting progress. Source bytes/catalogue links are outside current JSON backup; downloading again can reconnect a matching restored book through content deduplication. Native network acceptance is tracked separately in progress.md.
- `AiHandoff.tsx` prepares editable explanation, summary, flashcard and study-note prompts with bounded context and keeps its transient draft across in-app navigation. Clipboard copy and explicit provider opening are user actions. `handoff.rs` accepts known provider IDs and opens fixed HTTPS websites through the OS without putting context in URLs or submitting prompts. AI replies are not automatically read/imported. Study Hub previews bounded pasted card/quiz replies (JSON, tables and marked text) before native persistence. Direct AI generation remains outstanding parity work.
- Settings JSON in the same Rust-owned SQLite database stores bounded listening queues, vocabulary and pronunciation rules. New fields deserialize with defaults for existing libraries. Queue references and vocabulary source positions are validated natively; book deletion removes queued references and detaches vocabulary without deleting definitions. Failed optimistic preference changes revert to the last native-persisted snapshot. `reading_tools.rs` performs speech-only pronunciation edits before synthesis, preserving displayed text and source indices; regex is used for Unicode-aware literal phrase matching and boundary checks.
- `transfer.rs` owns desktop JSON backup validation/merge and text/Markdown/WAV serialization. Backups use `vern.desktop.backup.v1` and are bounded to 64 MB and 20,000 entries per top-level collection. Validation uses the normal native validators against an isolated in-memory database before returning counts and an opaque, single-use confirmation token. Restore merges in a SQLite savepoint with rollback on failure, preserving existing identities/progress/schedules. Queue, vocabulary and pronunciation data merge independently of the optional reader-preference restoration. Native save dialogs choose destinations; exports use sibling staging files, sync, and rename. Voice models/source attachments and Android backup migration are outside this format. Audio export currently synthesizes one anchored passage as 16-bit mono PCM WAV.
- Speech uses upstream `sherpa-onnx` Rust bindings and the same model families as Android. **Studio = Kokoro; Lite = Piper.** Static native linking is preferred so the installed app needs no developer runtime or Python/Node helper. Native archive acquisition happens at build time; models are downloaded by the app.
- A blocking speech worker owns the loaded engine. Requests carry a generation counter; obsolete synthesis is cancelled and its results discarded. The webview plays generated PCM WAV via Web Audio. Highlighting is per chunk, with progress advanced on completion. No word timing is claimed.
- Downloads have two execution slots, cancellation flags, temporary staging, bounded safe archive extraction and model validation before atomic publication. URLs are fixed catalogue entries, never frontend-supplied destinations. Failed/interrupted staging never counts as installed.

## Dependency purposes

React/React DOM: interface. TypeScript 6: typed command payloads (TypeScript 7 is beyond the lint tooling's supported range). Vite/React plugin: build and dev server. Tauri API/CLI: IPC and native packaging. `fflate`: bounded EPUB ZIP data. `@xmldom/xmldom`: EPUB XML/XHTML parsing inside a worker. `pdfjs-dist`: PDF text extraction and worker. ESLint 10/Prettier: source checks. Vitest/Testing Library: import and UI behavior. Playwright: browser inspection (independent of native checks).

Rust: `tauri`/`tauri-build` host and build integration; `tauri-plugin-dialog` native chooser (Rust-only API, so no unused JavaScript dialog package/permission is installed); `rusqlite` with bundled SQLite is the sole database owner; serde/serde_json command payloads; reqwest/rustls fixed HTTPS model downloads with the ring provider to avoid an AWS-LC/CMake dependency; tokio worker coordination; tar/bzip2 model archives; sha2 content integrity and deduplication; uuid note identifiers; sherpa-onnx native offline speech; unicode-normalization speech cleanup.

Download catalogue digests were verified against the official GitHub `tts-models` release asset metadata and the downloaded bytes on 17 October 2026. Lessac: `f1c6d0295cf16087b05f80fdca5b44daca5cd78e2c425d419a42ba34929805f9`. Kokoro v1.0: `4c3052abaa60943a341f193888cf6abd68787dae6ab8ae5c925a706caa247e4e`. Changed upstream assets require a deliberate catalogue update. Cancellation is checked between streamed reads and extraction entries; blocked network operations have a 20-second timeout. Downloads are restarted rather than resumed. Native inference remains sequential; the frontend now prefetches at most one future passage while current audio plays. Prefetch failures are handled immediately, and stale generations are discarded. This is not sample-accurate gapless scheduling or measured latency improvement. A transient sleep deadline schedules current Web Audio source stopping and prevents continuation. Android DSP parity remains later work.

## Source inventory and migration decisions

See [feature parity](desktop-feature-parity.md) for source references. The prior Kotlin desktop implementation has JSON storage, PDFBox parsing, a Windows PowerShell/System.Speech host and Compose workstation layouts. It supplies useful feature vocabulary but is not used as the runtime: it neither provides the selected Tauri stack nor the required neural voices.

## Release preparation

Native runners build Windows x64, Linux x64, and macOS Intel/Apple Silicon. CI builds are unsigned validation artifacts until signing is configured. Windows needs Authenticode; macOS needs Developer ID, hardened runtime, notarization and stapling. Linux needs distro/WebKitGTK compatibility validation. Audit model licences and include upstream runtime notices before distribution. Models remain optional app downloads, never require npm or Cargo on end-user machines. Configure an updater only after establishing signed release artifacts, a signing key outside the repo and an HTTPS update endpoint. No updater permission is granted yet.

`quizzes.rs` owns quiz validation, source references, saved attempts/best and last correct-answer counts. Submission supplies option indices; native code computes scores. Question edits reset old scores, title edits preserve them. Card imports use a savepoint and reject the entire batch on a validation failure. Quiz data is included in version-1 desktop backups with a default for older files; restore validates and merges without replacing existing quiz identities.

`notes.rs` owns standalone notes/checklists, notebook labels, colours, pinning and Trash state, with native timestamps and limits. Notebook removal unlinks labels transactionally while preserving notes. Permanent deletion requires an already trashed note. `NotesWorkspace.tsx` embeds My notes, Book notes/bookmarks and Trash within the Notes destination. Native backups validate label references and merge notebooks before notes, retaining existing identities. Media, reminders and note revision history remain separate parity work.
