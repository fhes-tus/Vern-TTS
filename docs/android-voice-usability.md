# Android voice selection and offline reliability — 4 November 2026

This follows the cloud-voice hardening checkpoint `fc01a45`. Changes are scoped to Android; unrelated desktop and release work is preserved.

## Voice page and guidance

The active narrator stays visible. Voice lists are grouped by engine and start collapsed, with counts and an accessibility state. Search reveals matching rows; active downloads remain visible while a group is closed. Downloadable packages are behind a separate disclosure. The catalog currently exposes 24 Studio voices, 12 Lite voices and eight Kitten voices. System voices depend on the phone and selected engine.

The revised, once-per-version explanation says that Vern starts with the phone's selected speech engine, whose voices can be offline, online or neural. **Use phone voice** explicitly selects the system default and disables personal cloud narration; **Explore voices** dismisses the explanation without changing the current connection. The help action reopens it. Each download requires an explanatory popup with the actual catalog size and the model's performance caveats. Cloud connection help explains personal billing, transmission of passage text, trusted servers, and the limits of custom API compatibility. All new text has the existing five preview translations.

Download labels use the official archive byte sizes expressed in MB using 1,048,576 bytes per displayed MB: Studio approximately 126.2 MB once, Lite approximately 64.1–76.6 MB per voice, and Kitten approximately 60.9 MB once. Installation needs extra temporary space. These are download sizes, not RAM requirements or promises of synthesis speed. Offline voices no longer display invented numerical quality/latency scores.

## Offline download changes

`VoiceArchiveCatalog` pins SHA-256 and size for all 14 offered archives, checked against the [publisher's release asset metadata](https://api.github.com/repos/k2-fsa/sherpa-onnx/releases/tags/tts-models). Model versions are selected for runtime and speaker-table compatibility, not merely the largest version number. Studio keeps the compatible English speaker ordering in its existing package.

`VoiceArchiveDownload` replaces the downloader's Boolean failure result. Connection, read timeout, host unavailable, rate limits, storage and integrity failures have distinct local messages. Public GET failures have at most three attempts. Resume requires an ETag or Last-Modified validator tied to the original URL, sends Range/If-Range, validates Content-Range and any returned validator, and replaces rather than appends if the server sends a full 200 response. Missing validators cause a fresh download. Unsafe redirects, mixed ranges, oversized/incomplete archives and checksum mismatches cannot become installed models. Verified partial bytes survive an interrupted attempt for a later retry. Successful partials are moved into the existing staging/install path; working models are not overwritten by incomplete downloads. No alternate unverified mirror was added.

## Ryan investigation

The user identified Ryan and clarified that garbling occurs intermittently at normal speed and pitch. The current official Ryan archive URL returned HTTP 200, and its default synthesis settings match those used by Vern. Normal pitch already bypasses pitch transformation, so blaming a non-default pitch effect would not explain this report.

Native diagnostics use isolated models and public test sentences, including numbers, abbreviations, curly quotes, compound punctuation and a longer sentence followed by an ordinary sentence. The first Samsung run generated 18 clips across Ryan and two Kitten speakers. A local Whisper tiny.en check recognized the Ryan test set coherently, with some recognition/pronunciation ambiguity on the longer sentence. It did not reproduce severe gibberish. This automated check is not a listening panel or proof that arbitrary books are correct. No user's book audio was captured or uploaded.

A second, approximately 700-character repeated passage exercised the long-input guard. Whisper base.en recognized all three repeated passages (tiny.en skipped one repetition), with ambiguity on “crossed” and “climbed past.” No omitted repetition was established in the generated audio. A separate native diagnostic generated default and zero-duration-noise variants; the phone disconnected before those last clips could be copied for comparison, so the published Ryan defaults remain unchanged. Do not describe the chunk safeguard as a confirmed fix for every intermittent model pronunciation failure.

Added a mitigation for unusually long Piper input: native requests are capped at 320 UTF-16 units on whitespace/grapheme boundaries, then all generated audio is joined. Ordinary short sentences are unchanged. Unit tests preserve every input character, including combining marks and surrogate pairs. This reduces long-call alignment risk; it is not claimed to prove or cure the original intermittent issue. An exact affected sentence and its source formatting remain useful to establish the cause. Model corruption, text preparation and model-specific pronunciation remain diagnostic candidates; download verification now excludes corrupted future archives from that list.

## Kitten and Paradee

Kitten uses the [official Sherpa-compatible Nano 0.8 FP32 archive](https://k2-fsa.github.io/sherpa/onnx/tts/all/English/kitten-nano-en-v0_8-fp32.html), eight speakers at 24 kHz, with its own tokens, pronunciation data and reference-style table. Its metadata is supported by the already-bundled runtime, so no native library or Gradle dependency upgrade was needed. Kitten has a distinct engine identity, download package, reading/preview path and portable export routing. It is labelled **Kitten**, while Piper and Kokoro retain **Lite** and **Studio**. This offline model is distinct from the hosted Kitten-TTS 2 cloud option. The archive's license and README are retained.

[Paradee's current repository](https://github.com/sahilmahendrakar/paradee) describes a separate v1.2 ONNX contract with four English voices and a Misaki-compatible phoneme vocabulary. Its graph inputs differ from the bundled runtime's supported Kitten/Kokoro models. Correct pronunciation requires its own frontend and adapter; passing it through an existing engine would risk wrong or missing words. It is therefore not advertised as an installable offline voice. Its small downloadable model alone does not establish an Android integration. A separately hosted Paradee server can use the existing custom connection if that server implements the supported speech request/response contract.

Custom API support remains exact HTTPS OpenAI-compatible speech JSON with a model ID, voice ID, optional personal key, and MP3/WAV output. Arbitrary REST formats, authentication schemes or streaming protocols require dedicated adapters. Requests go directly from the phone to the chosen server; the team does not supply a shared provider key. Security, provider retention, account charges, changing contracts, redistribution rights and support burden remain part of evaluating each additional provider.
