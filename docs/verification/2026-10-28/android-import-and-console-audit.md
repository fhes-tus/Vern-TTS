## Import and scan changes

- One format policy now controls browser eligibility, system chooser MIME types and extraction dispatch. Unknown files no longer default to text. `.aab`, APKs, generic ZIPs and formats without a shipped parser are rejected. A conflicting MIME hint cannot override an unsupported filename extension. Generic binary MIME associations were removed from the reader's SEND/VIEW filters.
- Preview metadata/header access runs on IO inside exception handling. Workers validate independently, including batch/shared/direct imports. Header checks and decoded-text checks reject binary data masquerading as text. Input limits are 16 MB for text/HTML, 32 MB for photos and 64 MB for other documents. Existing bounded archive processing remains in use.
- Failed imports clear busy state and leave the library usable. A rejected batch item does not stop subsequent items. Import messages now display and are consumed once; the native tests exposed that the current UI had no consumer for these messages. Completed workers retain their idempotent success path even after a temporary source disappears.
- **Add → Scan / OCR** offers **Take photo** and **Choose photo**. Capture uses the installed camera through `TakePicture` and a narrow FileProvider path; choosing uses `PickVisualMedia(ImageOnly)`, with Android's supported fallback. Both feed the existing import preview and OCR extraction flow. No camera or broad photo permission was added.
- Capture destinations survive activity/process recreation through saved pending state and app-owned temporary files. Cancellation, failed/empty capture, dismissed import and completed workers clean only their owned captures. Abandoned captures expire after seven days and are excluded from Android backup/device transfer.
- The platform image decoder preserves EXIF orientation while targeting at most 4 million pixels / 2560 pixels per side. Compressed input is bounded before decoding. Original-photo viewing reuses this limit; notification fallback uses at most 512×512. OCR pixels stay alive until the noncancellable ML Kit task finishes, then are recycled.

It owns extracted-page swipe/vertical-scroll layout, text swipe effects and original PDF swipe/scroll mode. These controls moved out of Customization. Text size, line spacing and paper tone are absent from this appearance page; the reader/player retains its contextual controls.

Each saves the actual reader preferences. Native PDF Document Tools likewise expands Reading layout in place; its former single-choice dialog was removed. Native PDF Swipe and Fit to Screen use distinct icons.

Its viewport reserves the measured toolbar/player areas even while chrome is hidden; search, contents, first/last, jump and speech-sync destinations share the same layout-aware navigation. Fitted vertical drags cannot expose the stack; zoomed panning, selection and multitouch remain available. Scroll restores the native continuous layout and its original viewport. Native checks assert one visible page, all four page edges within the viewport clear of controls, actual forward/back turns, same-page jumps, zoom/selection gating, scroll and preference restoration.

The real ReaderScreen/Listen host is checked through its resize control and persisted settings, with extracted size retained.
- Study-guide PDF export moved out of both reader tool menus into Study Hub. It prompts for a saved book, reads that book's text/annotations/booknotes on IO and opens the existing PDF share flow. - Restored the shared stable Funky cards transform on Added grid tiles, Home recent-book tiles, the Today card, the empty-library card and Study Hub's material buttons. ## Missing covers and Good Vibes extraction

- Replaced the faux-cloth/monogram missing-cover component with a flat typographic jacket: the actual title, known author when supplied, source format and a stable page-fold composition. Eight palettes have explicit contrasting ink. Generated images are bounded to 400×600 and share the existing 8 MB memory cache; they are not written over real artwork or saved as book data. Library/Home placeholders, book-details preview, Listen, extracted-reader artwork, notification fallback, reading/player widgets and quote cards share the renderer. Details resolve the shared loader on IO; widgets preserve aspect ratio within 256 pixels. Extracted and bundled covers keep priority.
- Inspected the user's exact 223-page PDF from the phone and its existing saved text. Pages 2–3 retained every native word. Contents pages 4 and 5 each lost three occurrences of “Introduction”: the existing cleaner inferred a repeated header from a five-page batch and removed matching lines anywhere on the page. That cleaner predates this task's file validation and managed-PDF changes. Protected structural/contents headings and limited repeated-text removal to page edges; added focused regression cases.
- Page 1 is an image-only cover. Previously, sufficient native text elsewhere in the batch prevented the average-based OCR fallback. Blank text pages containing raster artwork now receive individual OCR when the existing automatic-OCR option is enabled. Already readable pages retain native extraction, and image-free blank pages do not trigger this extra OCR.
- The supplied PDF remains a local test fixture outside the APK/repository. Device verification compares every native word count on pages 2–5 and checks cover OCR. The optional repair checks the stored original's SHA-256, backs up saved text/metadata/annotations, replaces only pages 1–5, retains page 6 onward verbatim and remaps the saved reading position and annotations.
