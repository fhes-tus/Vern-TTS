## Work package C — Liquid Glass and theme consistency

Treat Liquid Glass as a coherent component design, with a prototype and measured rollout. Transparent flat color plus a thick bright edge is insufficient for the intended frosted material effect.

1. Establish a small material specification: background layering, surface tint/opacity, backdrop treatment, edge highlight, elevation/shadow, corner sizes, typography, active/pressed/disabled/focus states and motion. Keep the selected color palette separate from the material pack.
2. Build shared surfaces for the bottom navigation, mini-player, top tabs, cards and sheets. Start with Library + Notes and compare the same components in light, dark and high-contrast modes. Use a modest recognizable background beneath translucent chrome; avoid distracting decoration behind dense reading text.
3. Prototype actual backdrop treatment with capability/performance checks. Blur the background behind a surface while keeping foreground text/icons sharp. Do not assume that blurring the surface's own contents is backdrop blur. Evaluate an implementation/dependency before committing to one; no blur library is currently specified by this plan.
4. Prefer resolved, readable colors per component instead of lowering the entire Material ColorScheme's opacity. Dialogs, sheets and inputs need sufficient separation and contrast on their real background. Provide an opaque accessible appearance for unsupported/expensive effects and user-selected reduced transparency/high contrast. Preserve AMOLED intent.
5. Avoid live blur on every scrolling row. Restrict expensive effects to a small number of chrome surfaces, reuse background state where valid and test scroll/keyboard/reader-overlay interactions. Do not add a continuous shimmer or decorative infinite animation as the default.
6. Make motion purposeful: immediate press feedback; a single active-tab indicator; a stable mini-player; interrupted transitions settle on the user's latest destination. Respect reduced-motion settings. Avoid stacking scale/fade/slide effects on every screen and avoid changing all duration values globally.
7. Reuse the actual shared material in theme preview cards. Audit Vern Media, Material You and One UI for independent visual identities and component coverage; a pack should not change only card radii while navigation and sheets retain the same hardcoded treatment.
8. Keep theme switching independent of reader state. It must not reconstruct document text, clear selection/drafts, restart playback or alter saved progress. Perform changes in small reviewable stages with before/after screenshots and rollback boundaries.

Proposed validation: capture representative Library, Classics, Notes/editor, Study, import sheet, outline dialog, mini-player and settings views in light/dark/AMOLED/high-contrast/large-font configurations. Measure frame timing and allocations on the connected Samsung before/after the prototype under the same scroll/navigation actions. The target is a visually convincing material with no material regression in responsiveness, memory or readability; no numeric performance improvement is claimed before profiling.
